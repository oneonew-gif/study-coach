# Canvas 巡检

这里是巡检的**产出目录**，全部由 `~/.workbuddy/skills/study-coach/scripts/canvas_inspect.sh`（= `bin/sc inspect`） 生成。

```
inspection/
├── README.md        本文件
├── snapshots/       每次巡检抓的原始快照（JSON，机器读）
├── reports/         每次巡检的变动报告（Markdown，人读）
└── log.tsv          巡检流水：什么时候跑的、结果如何
```

## 巡检是干什么的

Canvas 上的东西会**在你不知情的时候变**：

- 老师改了课件（同一份 PPT 更新了内容，文件名没变）
- 老师加了新课件或删了旧的
- **截止日期被推迟或提前**
- 作业分值被调整
- 冒出新公告、新作业
- 课程被隐藏 / 退课

这些变化不会主动通知你，但会直接影响你的复习与作业安排。巡检就是把 Canvas 抓成快照、跟上一次比对，**只告诉你变了什么**。

## 怎么用

```bash
S=~/.workbuddy/skills/study-coach/scripts/canvas_inspect.sh

$S collect     # 抓一份快照存档（第一次跑，只建基线）
$S diff        # 跟上一次比对，出变动报告并打印
$S run         # collect + diff，一次跑完（日常用这个）
$S status      # 上次巡检时间、快照数、凭据状态
```

## 一条设计上的硬规矩：巡检前要先问

巡检**不会**自己偷偷跑。到点之后，Agent 会先发一条确认消息（说清这次要查什么），**拿到明确许可才执行**。

这条规矩是刻意的，写在 Skill 的硬红线里：巡检是只读操作，但**「不被通知就有人翻我账号」**这件事对使用者是可感知的，所以决定权交回给使用者。

如果到点了没有回应 —— 那就不巡检。**沉默不等于同意。**

## 读不到数据时不会给你假绿灯

没有 token、网址不通、学校禁用了 API —— 这时 `collect` 会**明确报错**并给出两条出路（修接入 / 走手动流派），而不是安静地输出一份「无变动」的报告。

这是刻意的：一份假的「无变动」会让你以为 Canvas 上什么都没发生，**比直接报错危险得多**。

## 局限（知道边界在哪）

- **分页上限**：已自动跟随 Canvas 分页（响应头 `Link: rel="next"`），单次最多翻 25 页（约 2500 条）；超出会告警，此时缩小查询范围
- **读不到成绩**：本巡检只看课程内容与作业，不抓分数（避免把成绩混进学习资料里）
- **公告接口因校而异**：部分学校限制，读不到时报告会标出来，不会假装没有公告
- **快照会累积**：想清理时删 `snapshots/` 里的旧文件即可，但**至少保留最近两份**，否则 `diff` 没有基准

## 巡检发现课件更新之后

`diff` 会在报告第三节列出「建议校准的课件」。**它只列、不动手** —— 校准（下载 → 提取 → 按课件原词校对既有笔记 → 更新题库）是重活，要先问过你。
